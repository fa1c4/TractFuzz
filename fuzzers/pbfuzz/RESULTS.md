# PBFuzz results

## DeepSeek fixed Magma campaign

The current author PBFuzz DSH plugin and Python engine ran against every one of the 60 frozen Magma bug/entry pairs in `docs/tractfuzz_magma_benchmarks.md`, using the OpenAI-compatible `deepseek-flash` credentials exported by `~/api_keys/set_api_key.sh`. This is the current author implementation with a fixed-binary monitor oracle, distinct from the older Zenodo launcher that requires Cursor authentication. The full per-row record is [fixed-60.csv](fixed-60.csv), generated by `scripts/pbfuzz_finalize_fixed.py`. Ignored raw evidence is under `results/pbfuzz/fixed/<BUG>/` and `results/pbfuzz/isolated/<BUG>/`.

Each campaign uses the exact frozen entry, a staged copy of its source, binary, Magma monitor and corpus, one PIER round, a three-minute PIER wall limit, up to 1,000 fuzz iterations and a six-minute process hard limit. The binary and monitor copies are hash checked. Some rows received clean retries after an initial failed setup or when a prior model session could potentially inspect baseline witness files; earlier attempts remain archived. The final method restricts the model's file reads with Landlock and temporarily hides the original target work directory. `PDF020` was also continued once with a larger ten-minute PIER budget; it remained without a verified PoV. Its attempt and generated-input scan are retained in the matrix.

An engine `SUCCESS` is independently checked by replaying its saved input three times on the original frozen binary through the Magma monitor. The matrix reports the engine phase and replay count separately. The generated-input scanner checks non-successful campaigns for any canary reach or trigger that the engine did not report. A PLAN or IMPLEMENT timeout is a bounded failure to finish, not evidence that its bug is unreachable.

The final current-run matrix has **60/60 attempted, 30/60 independently triggered 3/3**, with all 60 model runs using the Landlock read boundary. The engine reported 31 `SUCCESS` states; `PDF021` is the exception, because its saved input timed out in all three frozen-binary monitor replays and in a longer 20-second oracle check. The other 29 rows ended in PLAN (20), IMPLEMENT (6), REFLECT (1), or STOPPED (2). No generated-input scan discovered an additional 3/3 trigger. All replayed binary hashes match the frozen build; the current logs contain no paths to earlier baseline witness files.

`PNG005` generated 31 scanned inputs, 21 reaching and none triggering. `PHP002` generated 400 scanned inputs, 306 reaching and none triggering; its agent timed out in REFLECT. `PDF020` received the common fixed campaign and a longer continuation, with 20 generated inputs scanned and no observed reach or trigger. These are bounded observations, not unreachability conclusions. Earlier inputs for `TIF001`, `TIF002`, and `SQL010` triggered 3/3 in prior attempts, but their clean Landlock reruns timed out in IMPLEMENT, so they are excluded from the final 30; the earlier evidence remains under `results/pbfuzz/prior-attempts/`. A different fixed-binary PoV for `TIF006` succeeded 3/3 on its clean rerun, resolving the earlier author-pilot input's cross-revision timeout without relabeling that old input.

The latest attempt for each row consumed **2,380 reported model calls**, **2,991,584 uncached input tokens**, **117,194,752 cache-read tokens**, and **1,816,626 output tokens**. Their agent wall times sum to 18,524 seconds (5 h 8 m 44 s across parallel targets). These totals exclude archived retries, setup/build time, and model requests without usage records; they are not a billed cost. Raw per-session accounting is in `results/pbfuzz/usage.json`. The model was given exact canary source locations and Magma source containing `MAGMA_ENABLE_FIXES` branches. The fixed-binary monitor adaptation and these information advantages prevent a controlled relative-efficacy claim against the other baselines.

## Current author DSH pilot

Before the fixed-binary campaign, the current author implementation was run with the user-supplied `deepseek-flash` endpoint, the pinned `pbfuzz` Magma fork, a headless DSH profile, and fixed benchmark entry points. This separate pilot establishes the author-build workflow and cross-revision replay. Its source and entry status is in `applicability-60.csv`; `scripts/pbfuzz_audit.py` refreshes that earlier matrix in `results/pbfuzz/applicability-60.csv`.

The frozen replay uses the separate Magma revision `cec1fec38fdc510c2cb8e6ae690e738b1042cb8d` and its monitor, which reports reached and triggered canary counters. `results/pbfuzz/<BUG>-replay.json` records input and binary SHA-256, exact argv, three trials, exit codes, target faults and timeouts. ## Model and execution cost

`scripts/pbfuzz_usage.py` sums DSH `assistant/message` usage from each compressed session archive. The table separates uncached input, cached input and output tokens. `totalTokens` in the raw record includes cached input; the title-generation request has no usage record, so these figures are a lower bound on provider calls. The provider's USD tariff and actual billed amount were unavailable. Build/download/setup time was not timed for this pilot; the agent wall interval is `state.updated_at - state.started_at` and is a lower bound on complete reproduction time. Engine seconds are only the actual generator/fuzz session from `metrics.json`.

The agent read `MAGMA_ENABLE_FIXES` branches in the patched source during at least the PNG and SND runs. The current author launcher hid patch files but did not remove those branches from its built source. The campaign also supplied the exact `MAGMA_LOG` condition. These are information advantages relative to the other baselines in this repository and preclude a controlled efficacy claim from the first-input triggers. The five rows establish executable author workflow and replay evidence, not a fair relative performance estimate.

## Historical artifact and LibAFLGo adapter

The archived artifact prepared nine bugs; seven IDs intersect the fixed 60 and only four match the fixed program (`PNG006`, `SND001`, `SQL012`, `TIF006`). The 60-row DeepSeek campaign above uses the current author DSH implementation and the fixed-binary monitor adapter. It does not claim to execute the archived Cursor launcher or reproduce its `sonnet-4` cost and search behavior.

`PDF020` had an earlier pilot fixed-entry attempt that was stopped in PLAN after 395 seconds; its raw status is `results/pbfuzz/PDF020-interruption.json`. The final 60-row campaign and longer continuation are separate attempts. No PDF020 attempt is omitted from the evidence, and no unreachability inference is made.

The separate seed adapter was exercised on PNG006: it imported a 41-byte PoV and recorded generator ID, input SHA-256 and model-configuration hash. No LibAFLGo campaign has been run from that imported seed, so there is no PBFuzz + LibAFLGo outcome to report.

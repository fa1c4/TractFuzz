# Halo validation

`cargo +1.71.1 test -p libaflgo --lib --offline` passes four tests on equality (`byte[0] == 'H'`), interval (`3 <= byte[1] <= 8`), and linear (`byte[1] + byte[2] == 20`) observations. They verify generated values satisfy the selected predicate, sparse-positive fallback, misleading correlation, handling of a truncated negative input, and restoration of both pools from a checkpoint.

`scripts/test_halo_fixture.sh` compiles a standalone in-process target with those three conditions and checks its execution trace. The 2026-10-27 run archived under `results/halo/fixture/` recorded 513,088 observations, 7,629 target hits, 254,167 generated inputs, 8,017 inference passes, and four final candidates; its invariant trace includes the expected equality, interval, and sum relation. The raw input trace is compressed as `halo-inputs-v1.tsv.gz`, with file hashes in `SHA256SUMS`. A first fixture run exposed an empty-input length bug in inference; the byte-position comparison now uses the common-length majority. The Magma PNG006 and TIF006 campaigns serve as fixed-entry runner and oracle smoke tests.

The fixture intentionally points the static AFLGo pass at an absent source line and calls the target and distance callbacks inside its three-condition branch. The pass prints a target-not-found diagnostic during compilation; the fixture assertion checks the runtime callback observations. The Magma runs separately verify real source-line target instrumentation.

After final source formatting and wrapper isolation, the fixture passed again with 507,456 observations, 10,375 target hits, 254,609 generated inputs, and four final candidates. Its trace and hashes are archived under `results/halo/fixture-final/`. A separate six-second CLI smoke run after the rebuild recorded 128 observations and 119 generated inputs. The final Rust checks were `cargo +1.71.1 test -p libaflgo --lib --offline` (four passed) and `cargo +1.71.1 check -p halo -p halo_cli -p halo_control_cli --offline` (passed).

The implementation intentionally records false relations as candidates rather than claiming soundness. `halo-invariants-v1.tsv` contains discrimination, attempts, useful count, and smoothed similarity at each inference. `halo-inputs-v1.tsv` records sampled lineage, outcome, distance, and generation cost for inspection and replay. Unit tests do not establish agreement with unavailable author output.
